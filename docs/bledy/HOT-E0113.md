# HOT-E0113 — odinstalowanie nie skończyło się

## Znaczenie
`server-install.sh --uninstall --yes` nie usunął wszystkiego, co zainstalował. Są dwa przypadki:
- „The mod state cannot be copied before uninstalling”: nie powstała kopia `hot-state` i `hot-keys` w `/srv/horizon/backups/`. Skrypt wtedy niczego nie usuwa.
- „Some horizon-hot files cannot be removed”: usługi są już zatrzymane, ale część plików została. Pole `chain` wpisu wymienia te ścieżki.

Świat, kopie świata, logi i użytkownik `horizon` w obu przypadkach są nietknięte.

## Typowe przyczyny
1. Pełny dysk: `tar` nie zapisze kopii stanu modów.
2. Plik w użyciu albo system plików tylko do odczytu (np. po błędzie dysku zamontowany `ro`).
3. Uruchomienie bez `sudo`: skrypt wtedy kończy się kodem 2, zanim cokolwiek zrobi.

## Diagnostyka
- `df -h /srv/horizon` — czy jest miejsce.
- `tail -n 1 /srv/horizon/logs/install.jsonl` — wpis z polem `chain`.
- `mount | grep ' / '` — czy główny system plików nie jest `ro`.
- `systemctl list-units 'horizon-hot*'` — czy usługi są zatrzymane.

## Naprawa
1. Zwolnij miejsce albo usuń ręcznie ścieżki z `chain` (`sudo rm -rf …`).
2. Uruchom jeszcze raz: `sudo bash server-install.sh --uninstall --yes`. Drugie uruchomienie pomija to, czego już nie ma.

Całkowite usunięcie, razem ze światem: `sudo userdel horizon && sudo rm -rf /srv/horizon`.

## Co system robi sam
- Bez `--yes` tylko wypisuje, co usunie i co zostawi, i kończy się kodem 2.
- Przed usunięciem pakuje `hot-state` i `hot-keys` do `backups/hot-state-przed-odinstalowaniem-<data>.tar.gz`.
- Nie rusza pakietów systemowych, reguły zapory dla SSH ani samej zapory.
- Z `server.toml` usuwa tylko adres naszej paczki zasobów (bez serwera paczki gracze nie mogliby wejść), resztę ustawień zostawia.

## Kod
- `scripts/server-install.sh` (`uninstall`)
