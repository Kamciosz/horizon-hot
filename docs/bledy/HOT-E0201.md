# HOT-E0201 — `hotd` nie pobrał repo serwera

## Znaczenie
`git fetch` repo serwera się nie udał. `hotd` nie widzi nowych commitów, więc na serwerze nic się nie zmienia. Ten sam błąd trafia do logu raz, a nie co 10 s; gdy pobieranie znów działa, w logu pojawia się wpis informacyjny.

## Typowe przyczyny
1. Brak sieci albo GitHub nie odpowiada.
2. Repo prywatne, a klucz tylko do odczytu (deploy key) nie jest dodany w GitHubie albo nie ma go w `~/.ssh` użytkownika usługi.
3. Zły adres repo w usłudze `hotd` (`--repo`).
4. Uszkodzone lustro `hot-state/repo.git` (np. po zapełnieniu dysku).

## Diagnostyka
- `sudo -u horizon git ls-remote <adres repo>` — ten sam dostęp co usługa.
- `systemctl cat hotd` — adres repo i `GIT_SSH_COMMAND`.
- `grep HOT-E0201 /srv/horizon/logs/hotd.jsonl | tail -1` — pole `chain` ma dokładny komunikat gita.

## Naprawa
Napraw dostęp: sieć, klucz w GitHubie (Settings → Deploy keys) albo adres w usłudze. Uszkodzone lustro można usunąć (`rm -rf hot-state/repo.git`); `hotd` utworzy je od nowa w następnym kroku.

## Co system robi sam
Serwer działa z modami, które ma. `hotd` próbuje ponownie co 10 s.

## Kod
- `crates/hotd/src/git.rs` (`Mirror::fetch`)
- `crates/hotd/src/daemon.rs` (`Daemon::step`)
