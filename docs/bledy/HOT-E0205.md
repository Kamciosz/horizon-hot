# HOT-E0205 — silnik nie przyjął albo nie potwierdził zmian

## Znaczenie
`hotd` wysłał do silnika `hot load`, `hot unload` albo `hot slots`, ale komenda nie doszła, `hot-core` odrzucił plik albo w ciągu 60 s nie pokazał zmian w `hot-state/status.json`. W polu `cause` jest powód, często z kodem błędu `hot-core` (`HOT-E040x`).

## Typowe przyczyny
1. Silnik nie działa albo `hotd` ma inny `--engine-dir` niż silnik.
2. `hot-core` odrzucił bibliotekę: zła wersja ABI (`HOT-E0402`) albo zły plik (`HOT-E0401`).
3. Id w `hot_mod!(…, id = "…")` różni się od nazwy katalogu `mods/<id>/`.
4. Silnik bez `hot-host` (brak `hot-state/status.json`).
5. `hot-core` starszy niż `hotd`: na `hot slots` odpowiada samą instrukcją zamiast „Bloki modów: …”. Przydział jest już w `hot-state/slots.json`; nowy `hot-core` (`hot core load`) przeczyta go sam.

## Diagnostyka
- `horizon-server --dir <katalog> status` — czy silnik działa.
- `hot status` — linie `hot-core` i ostatnie błędy.
- `grep HOT-E04 <HOT_HOME>/logs/hot-core.jsonl | tail -3`.

## Naprawa
Uruchom silnik albo popraw `--engine-dir` w usłudze `hotd`. Dla błędów `hot-core` przeczytaj wpis z jego kodem w `docs/bledy/`. Przy różnym id zmień `id` w `hot_mod!` albo nazwę katalogu i wypchnij commit.

## Co system robi sam
`hotd` zapamiętuje commit jako nieudany i go nie ponawia. Mody, które zdążyły się przełączyć, zostają; reszta działa na poprzedniej generacji. Następny commit liczy zmiany od ostatniego udanego, więc wczyta je ponownie.
