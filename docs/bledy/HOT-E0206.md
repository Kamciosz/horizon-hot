# HOT-E0206 — silnik padł zaraz po commicie (zły commit)

## Znaczenie
W ciągu 60 s od zastosowania commita silnik przestał działać albo działa z innym PID, czyli został uruchomiony od nowa (D13). `hotd` oznacza commit jako zły i już go nie stosuje.

## Typowe przyczyny
1. Mod z tego commita wywraca cały proces (np. `abort`, przepełnienie stosu, błąd w `unsafe`), a nie tylko panikuje.
2. Mod zajmuje tyle pamięci, że system zabija silnik.
3. Ręczny restart silnika tuż po commicie (fałszywy alarm).

## Diagnostyka
- `tail -200 <katalog silnika>/logs/latest.log` z chwili z pola `ts`.
- `journalctl -k | grep -i oom` — zabicie przez brak pamięci.
- `git show <commit>` w repo serwera — co się zmieniło.

## Naprawa
Popraw mod zmieniony w tym commicie i wypchnij nowy commit. Przy fałszywym alarmie wystarczy pusty commit (`git commit --allow-empty`).

## Co system robi sam
Commit trafia na listę złych, `hotd` wraca do poprzedniego zastosowanego commita. Po restarcie `hot-core` ładuje ostatnie dobre generacje modów.

## Kod
- `crates/hotd/src/daemon.rs` (`check_crash`)
