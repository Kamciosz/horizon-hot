# HOT-E0208 — paczka danych moda nie weszła

## Znaczenie
`hotd` nie przygotował paczki danych z `mods/<id>/data/` albo silnik nie włączył jej po `reload`. Commit nie został zastosowany; świat ma te paczki danych, które miał wcześniej.

## Typowe przyczyny
1. Plik `.json` w `mods/<id>/data/` nie jest poprawnym JSON-em (nazwa pliku w `context.file`, miejsce błędu w `cause`).
2. W `mods/<id>/data/` jest dowiązanie symboliczne; paczka przyjmuje tylko zwykłe pliki.
3. Paczka `file/hot-<id>` jest na liście `disabled` w `<świat>/datapacks.json` (ktoś wyłączył ją komendą `/datapack disable`), więc po `reload` zostaje wyłączona.
4. Pełny dysk albo katalog świata należy do innego użytkownika niż usługa `hotd`.

## Diagnostyka
- `hotd status` — powód ostatniego nieudanego commita.
- Wpis `HOT-E0208` w `<HOT_HOME>/logs/hotd.jsonl`: `context.file`, `context.not_enabled`, `chain` (odpowiedź silnika na `datapack list`).
- `python3 -m json.tool mods/<id>/data/<plik>.json` w repo serwera.
- `horizon-server --dir <katalog serwera> cmd datapack list`.
- `cat <świat>/datapacks.json`, `ls -l <świat>/datapacks/`, `df -h <świat>`.

## Naprawa
Popraw plik w repo serwera i wypchnij nowy commit. Paczkę wyłączoną w `datapacks.json` włącz komendą `/datapack enable "file/hot-<id>"` albo usuń ją z listy `disabled`, potem wypchnij commit. Przy błędzie zapisu zwolnij miejsce albo popraw właściciela (`chown -R horizon: <świat>/datapacks`).

## Co system robi sam
Zły plik jest wykrywany, zanim silnik cokolwiek dostanie: świat się nie zmienia. Gdy silnik nie włączył paczki, `hotd` przywraca poprzednie paczki z `<świat>/.hot-staging/old/` i wysyła `reload` jeszcze raz. Mody z kodem przełączone w tym samym commicie zostają. Następny commit liczy zmiany od ostatniego udanego.
