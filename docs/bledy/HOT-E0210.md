# HOT-E0210 — paczka zasobów nie powstała albo nie jest podawana

## Znaczenie
`hotd` nie zbudował paczki zasobów z `mods/<id>/assets/` (wygląd i nazwy bloków ze slotów) albo `hotd serve-pack` nie może podać jej graczom. Przy błędzie budowy commit nie został zastosowany i gracze dostają poprzednią paczkę.

## Typowe przyczyny
1. Plik `mods/<id>/assets/blocks/<nazwa>.png` nie jest obrazem PNG.
2. `mods/<id>/assets/lang.json` nie jest obiektem JSON z napisami (`{"<nazwa>": "Nazwa w grze"}`).
3. Pełny dysk albo `hot-state/pack/` należy do innego użytkownika niż usługa `hotd`.
4. `serve-pack`: port (domyślnie 8131) zajęty albo zablokowany w zaporze.

## Diagnostyka
- `hotd status` — powód ostatniego nieudanego commita.
- Wpis `HOT-E0210` w `<HOT_HOME>/logs/hotd.jsonl`: `context.file`, `cause`.
- `file mods/<id>/assets/blocks/*.png` w repo serwera.
- `curl -sI http://<serwer>:8131/pack.zip` — czy paczka jest podawana; `ss -ltnp | grep 8131`.
- `ls -l <HOT_HOME>/hot-state/pack/`, `df -h <HOT_HOME>`.

## Naprawa
Popraw plik w repo serwera i wypchnij nowy commit. Przy zajętym porcie zatrzymaj to, co go zajmuje, albo uruchom `hotd serve-pack --port N` i zmień `resource-pack` w `server.toml` (zmiana adresu wymaga restartu silnika). Przy błędzie zapisu zwolnij miejsce albo popraw właściciela (`chown -R horizon: <HOT_HOME>/hot-state`).

## Co system robi sam
Zły plik jest wykrywany, zanim cokolwiek się zmieni: gracze dostają poprzednią paczkę, a przydział slotów zostaje. Paczka podmienia się w całości (plik tymczasowy i zmiana nazwy), więc gracz nigdy nie pobierze połowy pliku.

## Kod
- `crates/hotd/src/pack.rs` (`build`, `serve`)
- `crates/hotd/src/daemon.rs` (`Daemon::update_pack`)
