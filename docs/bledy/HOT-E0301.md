# HOT-E0301 — silnika z hot-host nie da się zbudować

## Znaczenie
`hotd build-engine` (instalator, obraz) albo aktualizacja Horizona (`hotd horizon`, M9) nie zbudowały silnika z `hot-host`. Budowę robi `horizon-launcher native-build --server-output`. Rewizję Horizona wybiera przypięcie `horizon_revision` w kopii paczki `hot-host`, a wersja bazowa (dowolne zainstalowane wydanie albo Nightly) daje tylko przygotowane pliki gry (ADR 0012). Pole `context.rev` podaje budowaną rewizję, `context.base` wersję bazową, `chain` ostatnie linie launchera.

## Typowe przyczyny
1. Brak zgody właściciela na kod natywny (`--trust-native-code`). Tej zgody nie daje agent.
2. Wersja bazowa nie jest przygotowana: launcher pisze „is not prepared yet”. Na serwerze nikt nie przygotował plików gry dla użytkownika `horizon`.
3. Nowa rewizja Horizona przesunęła miejsce, w które wchodzi mixin `wait_for_world` (`WorldRequest::prepare_world`), albo zmieniła API haków: `horizon-mixins apply` albo kompilacja pada.
4. Brak sieci: launcher pobiera źródło rewizji z GitHuba (`codeload.github.com`, tag `nightly-source/…`).
5. Brak `horizon-launcher` pod podaną ścieżką.

## Diagnostyka
- `chain` wpisu: słowa launchera.
- `sudo -u horizon -H horizon-launcher versions --installed` — jakie wersje są zainstalowane.
- Log budowy launchera: `native/build.log` w folderze danych launchera użytkownika `horizon` (`~horizon/.local/share/horizon-launcher/`).

## Naprawa
- Brak zgody: przeczytaj `crates/hot-host`, potem uruchom instalator z `--trust-native-code` (aktualizacja: `hotd horizon --trust-native-code`, opis w `docs/aktualizacje.md`).
- Brak przygotowania: `sudo -u horizon -H horizon-launcher account sign-in`, potem `sudo -u horizon -H horizon-launcher prepare --download`.
- Mixin nie pasuje do nowej rewizji: popraw `crates/hot-host/horizon-mixin.toml` i `wait_for_world.rs` dla nowego Horizona; do tego czasu serwer zostaje na starej rewizji.

## Co system robi sam
Usuwa niedokończony folder silnika i kopię paczki. Działający silnik się nie zmienia. Aktualizacja oznacza rewizję jako nieudaną i nie buduje jej ponownie (`hot-state/horizon.json`, pole `bad`).
