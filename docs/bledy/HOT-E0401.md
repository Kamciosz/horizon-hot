# HOT-E0401 — pliku moda gorącego nie da się wczytać

## Znaczenie
`hot-core` dostał polecenie `hot load <plik>` (od `hotd` albo z konsoli), ale nie wczytał pliku jako moda. Plik nie został włączony, a poprzednia generacja moda działa dalej. Pole `context.source` wskazuje plik, a `chain` zawiera komunikat systemu (`dlopen`) albo błąd kopiowania.

## Typowe przyczyny
1. Plik zbudowano na inną architekturę niż serwer, np. x86_64 zamiast aarch64.
2. Plik nie jest biblioteką `cdylib` albo nie eksportuje `hot_mod_entry`, bo mod nie wywołuje `hot_sdk::hot_mod!`.
3. Id moda ma niedozwolone znaki. Dozwolone są `a-z`, `0-9`, `_` i `-`, najwyżej 64 znaki.
4. Brak miejsca na dysku albo brak prawa zapisu do `hot-state/gen/`.

## Diagnostyka
- `uname -m` na serwerze i `file <plik>`: architektury muszą się zgadzać.
- `nm -D <plik> | grep hot_mod_entry` (macOS: `nm -gU`): symbol musi być w pliku.
- `df -h` i `ls -ld hot-state/gen`.

## Naprawa
Zbuduj mod przez CI repozytorium serwera na architekturę serwera i wyeksportuj go makrem `hot_sdk::hot_mod!(Typ, id = "...", version = "...")`. Potem wypchnij zmianę albo uruchom `hot load` jeszcze raz.

## Co system robi sam
Nic nie przełącza. Mod zostaje w poprzedniej generacji albo nie zostaje włączony, jeśli był nowy. Błąd trafia do `hot-state/status.json` (`recent_errors`).

## Kod
- `crates/hot-core/src/loader.rs` (`open`, `copy_and_open`)
