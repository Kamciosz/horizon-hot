# HOT-E0406 — `hot-host` nie wczytał `hot-core`

## Znaczenie
Mod natywny `hot-host` nie wczytał rdzenia przy starcie serwera albo podczas `hot core load`. Serwer działa dalej, ale bez modów gorących. Wpis jest w `logs/latest.log` serwera, nie w `logs/hot-core.jsonl`, bo rdzeń jeszcze nie działa. W linii jest ścieżka pliku i powód (`there is no such file`, `cannot be opened`, `ABI`, `init failed`).

## Typowe przyczyny
1. Brak pliku: `<HOT_HOME>/hot-core/libhot_core.so` (na macOS `.dylib`) nie istnieje, a `HOT_CORE` nie wskazuje innego.
2. Plik zbudowany na inną architekturę albo system (np. `.dylib` z Maca na Ubuntu).
3. `hot-core` i `hot-host` z różnych wersji ABI (`the core uses ABI …`).
4. `init` rdzenia się nie udał; przyczyna jest w liniach tuż nad tą, zwykle z kodem HOT-E0404 (brak praw zapisu do `hot-state/` albo `logs/`).

## Diagnostyka
- `ls -l "$HOT_HOME/hot-core/"` i `file <plik>` — czy plik jest i czy pasuje do `uname -m`.
- `grep -n 'HOT-E04' logs/latest.log` — linie przed tą mówią, co padło w `init`.
- `echo $HOT_HOME $HOT_CORE` w środowisku usługi (`systemctl show horizon-hot -p Environment`).

## Naprawa
Zbuduj rdzeń na tej maszynie albo w CI dla jej architektury: `cargo build --release -p hot-core`, skopiuj `target/release/libhot_core.so` do `<HOT_HOME>/hot-core/` i wpisz w konsoli `hot core load`. Przy niezgodnym ABI zbuduj `hot-host` i `hot-core` z tego samego commita.

## Co system robi sam
- Przy starcie: serwer działa bez modów gorących; nic nie jest kasowane.
- Przy `hot core load`: jeśli nowy rdzeń nie wystartuje, poprzedni startuje ponownie z tym samym stanem. Gdy i to się nie uda, mody gorące są wyłączone do następnego `hot core load` albo restartu.

## Kod
- `crates/hot-host/api/src/lib.rs` (`start`, `swap_core`, `open_core`)
