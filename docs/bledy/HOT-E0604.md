# HOT-E0604 — zła konfiguracja proxy

## Znaczenie
`hot-proxy` nie wystartował: nie ma sekretu, nie może słuchać na porcie, nie zrobił klucza RSA albo tryb offline miałby działać na adresie innym niż lokalny.

## Typowe przyczyny
1. Plik z `--secret` nie istnieje albo jest pusty.
2. Port graczy (domyślnie 25565) zajmuje inny program, np. silnik ze starej instalacji.
3. `--offline` razem z `--listen` innym niż 127.0.0.1. Proxy tego odmawia, bo każdy mógłby wejść bez kupionej gry.
4. System nie daje liczb losowych do klucza RSA.

## Diagnostyka
- Wpis `HOT-E0604` w `<HOT_HOME>/logs/hot-proxy.jsonl` albo na stderr procesu (`journalctl -u horizon-hot-proxy -n 50`): `what`, `context.file` albo `context.listen`.
- `ss -ltnp | grep 25565` — kto zajmuje port.
- `ls -l <plik sekretu>` — czy istnieje i nie jest pusty.

## Naprawa
Wskaż w `--secret` plik `forwarding.secret` silnika. Zwolnij port albo przenieś silnik na inny port (silnik słucha na 127.0.0.1, port graczy należy do proxy). Usuń `--offline` z polecenia proxy i uruchom je ponownie. Na serwerze z instalatora: `sudo systemctl restart horizon-hot-proxy` po naprawie; instalator nigdy nie ustawia `--offline`.

## Co system robi sam
Nic: proxy kończy działanie, a systemd uruchamia je ponownie według ustawień usługi.
