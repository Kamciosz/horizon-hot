# HOT-E0704 — sprawdzenie nowego Horizona się nie odbyło

## Znaczenie
`hotd horizon` nie zdołał sprawdzić nowej rewizji Horizona. Nie odczytał tagów `nightly-source/…` albo `Cargo.lock` z GitHuba, albo nie dało się przeprowadzić samego testu na kopii świata (brak kopii zapasowej, stary silnik nie wstał, boty nie weszły do starego silnika). To nie jest wina nowej rewizji: nie trafia ona na listę `bad`.

## Typowe przyczyny
1. Brak sieci albo GitHub nie odpowiada.
2. Brak `git` na serwerze.
3. Brak `horizon-bots` (flaga `--bots`) albo kopii zapasowej, której nie da się zrobić.
4. Stary silnik nie wstaje na kopii świata: zły `server.toml`, brak plików gry.

## Diagnostyka
- `chain` wpisu w `logs/hotd-horizon.jsonl`.
- `git ls-remote --tags https://github.com/horizon-rust/horizon 'refs/tags/nightly-source/*'`
- `<home>/hot-trial/logs/supervisor.log`, gdy padł test.

## Naprawa
Napraw przyczynę z `chain`. Usuwać niczego nie trzeba: `hotd horizon` ponawia co godzinę i bierze gotowy już silnik zamiast budować go od nowa.

## Co system robi sam
Ponawia co godzinę. Serwer zostaje na swojej rewizji.

- `crates/hotd/src/update_env.rs` (`newest`, `cargo_lock`)
- `crates/hotd/src/trial.rs` (`run`)
