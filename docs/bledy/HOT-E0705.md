# HOT-E0705 — nowej wersji horizon-hot nie da się sprawdzić ani zbudować

## Znaczenie
`hotd upgrade` nie zdołał pobrać nowej wersji horizon-hot z repozytorium podanego przy instalacji, porównać jej z wersją na serwerze, zbudować jej, podmienić plików albo silnik nie potwierdził wczytania nowego `hot-core`. To nie jest wina samej wersji: nie trafia ona na listę `bad`, a `hotd upgrade` spróbuje znowu po dobie.

## Typowe przyczyny
1. Brak sieci albo GitHub nie odpowiada.
2. Kompilacja się nie udaje: za mało pamięci, brak pakietu systemowego, uszkodzony `target/` w klonie.
3. Nowy program nie odpowiada na `--help` (zła budowa).
4. Brak uprawnień do `bin/` albo `hot-core/` (zły właściciel plików).
5. Silnik nie odpowiedział na `hot core load` (nie działa, trwa podmiana silnika) albo odpowiedział inaczej niż „Rdzeń podmieniony”. Działa poprzedni `hot-core`.

## Diagnostyka
- `chain` wpisu w `logs/hotd-upgrade.jsonl`.
- `journalctl -u horizon-hot-upgrade -n 50`
- `sudo -u horizon git -C /srv/horizon/src/horizon-hot fetch` sprawdza sieć i dostęp do repozytorium.

## Naprawa
Napraw przyczynę z `chain`, potem uruchom krok od razu: `sudo systemctl start horizon-hot-upgrade`. Sprawdzenie raz na dobę liczy się od ostatniej próby; żeby ponowić wcześniej, usuń pole `checked_at` z `hot-state/upgrade.json` albo uruchom instalator ponownie.

## Co system robi sam
Ponawia po dobie. Serwer zostaje na swojej wersji, odłożone pliki są usuwane.

## Kod
- `crates/hotd/src/upgrade.rs` (`Upgrade::step`)
- `crates/hotd/src/upgrade_env.rs` (`fetch`, `build`, `load_core`, `install`)
