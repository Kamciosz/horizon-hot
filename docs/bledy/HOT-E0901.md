# HOT-E0901 — nie ma launchera Horizona i nie da się go zainstalować

## Znaczenie
`hot-play` nie znalazł działającego `horizon-launcher` (zmienna `HOT_PLAY_LAUNCHER`, własna kopia w folderze danych, `PATH`, `/Applications/Horizon.app`) i nie zdołał pobrać nowego z wydań `launcher@…` w `github.com/horizon-rust/horizon`. Bez launchera nie da się zainstalować ani uruchomić gry.

## Typowe przyczyny
1. Brak internetu albo GitHub nie odpowiada (także limit zapytań API GitHuba bez logowania: 60 na godzinę z jednego adresu).
2. Pobrany plik ma inną sumę SHA-256 niż `SHA256SUMS` (przerwane pobieranie, coś zmienia pliki po drodze).
3. System bez wydania launchera (na przykład Linux na ARM): są tylko macOS arm64 i x86_64, Linux x86_64, Windows x86_64.
4. Brak programu `tar` (Windows starszy niż 10 1803).

## Diagnostyka
- Plik `hot-play.jsonl` w folderze logów `hot-play` (macOS: `~/Library/Application Support/hot-play/logs`, Linux: `~/.local/share/hot-play/logs`, Windows: `%LOCALAPPDATA%\hot-play\logs`). „Napraw” zapisuje z niego raport `hot-play-raport.md` na pulpicie.
- Pole `context.system` mówi, dla jakiego systemu szukano pliku; `context.expected` i `got` pokazują różne sumy.
- `curl -sI https://api.github.com/repos/horizon-rust/horizon/releases` sprawdza dostęp do GitHuba.

## Naprawa
Sprawdź internet i wybierz „Graj” jeszcze raz. Na systemie bez wydania zainstaluj launcher ręcznie i wskaż go: `HOT_PLAY_LAUNCHER=/ścieżka/horizon-launcher hot-play`.

## Co system robi sam
Przy każdym „Graj” szuka launchera od nowa; zepsuty plik (nie odpowiada na `--version`) pomija i pobiera nowy do `<dane>/launcher`.

## Kod
- `crates/hot-play/src/real.rs` (`ensure_launcher`, `install_launcher`)
